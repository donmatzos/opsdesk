**Goal:** close the remaining resume gaps (GitLab CI templating, Jenkins, Ansible Tower, Artifactory, tagged releases, incident analysis, agent tooling) with artifacts that mirror the real GitHub Actions pipeline, and finish the repo for recruiters: a README with a "what this shows" table, a Mermaid architecture diagram, the full mock inventory and the Pages demo link.

**Architecture:** the real pipeline (`ci.yml`: verify, Sonar, gitleaks, Trivy fs, helm check, image + Trivy + `tools/ci-smoke.sh`, publish, gated OpenShift deploy with smoke test and rollback) is the single source; GitLab and Jenkins repeat the **same stages, same tools, same scripts** (`tools/smoke-test.sh`, `tools/ci-smoke.sh`, `trivy.yaml`). The GitLab template is configured only by variables (the thesis and the resume line "configure through their own environment variables"). Ansible deploys the same chart with the same values files and the same smoke/rollback logic as `deploy-dev`; the Tower/AWX job template is Terraform (`denouche/awx` provider), validated like `infra/terraform/datadog`. Every mocked artifact is linted/validated in a new CI job `templates` through one Docker-only script `tools/ci-templates-check.sh` (pattern of `tools/helm-check.sh`). A new `tools/docs_check.py` keeps README links, runbook links and the mock inventory honest.

**Tech Stack (pin exact versions at task start; resolve with `docker manifest inspect`, `npm view <pkg> version`, `curl -s https://registry.terraform.io/v1/providers/denouche/awx/versions`, SHA-pin actions with `git ls-remote`):** GitLab CI schema via `check-jsonschema --builtin-schema vendor.gitlab-ci` (image `python:3.13-slim`), `gitlab-ci-local` (image `node:24-alpine` + git), Groovy parse check (image `groovy:4.0-jdk21`), `ghcr.io/ansible/community-ansible-dev-tools` (ansible-core, ansible-lint), collection `kubernetes.core`, Terraform 1.17.1 + `denouche/awx`, tflint 0.66.0, `rhysd/actionlint`, `minlag/mermaid-cli`.

## Global Constraints
- **No secrets anywhere.** GitLab: only names of masked/protected CI/CD variables (`SONAR_TOKEN`, `OPENSHIFT_TOKEN`, `ARTIFACTORY_TOKEN`) and predefined `CI_REGISTRY_*`. Jenkins: only credential **IDs** inside `withCredentials`/`configFileProvider` (`sonarqube`, `artifactory-publisher`, `openshift-dev-token`, `artifactory-maven-settings`). Ansible: no vars with credentials, no vault file; the cluster token comes from the AWX "OpenShift or Kubernetes API Bearer Token" credential (injects `K8S_AUTH_HOST`/`K8S_AUTH_API_KEY`) or the local env. AWX Terraform: credential referenced by numeric ID variable; provider auth from env `AWX_HOSTNAME`/`AWX_TOKEN`. Maven: `${env.ARTIFACTORY_USER}`/`${env.ARTIFACTORY_TOKEN}` only, no defaults. Postmortems never repeat a leaked value. `gitleaks dir .` before every commit (only `deploy/compose/.env` may show up).
- Every mock: header `MOCK: <thing> — <why>, see docs/context/cloud-mocks.md` (`#` or `//` comment), a row in `cloud-mocks.md` and in the README mock table.
- Hosts are placeholders on `example.com` (`artifactory.example.com`, `gitlab.example.com`, `awx.example.com`); no real company names.
- `./mvnw verify` green before each commit; context files <= 100 lines / 6 KB (`python3 tools/context_check.py`).
- Branch `update/templates-and-polish`; one commit per task; push after each task; actions pinned by SHA (reuse the SHAs already in `ci.yml`).
