# Phase 6: Runbook RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** opsdesk answers operations questions from its own runbooks: `POST /api/assist` and the MCP tool `search_runbooks` retrieve runbook sections from an in-memory BM25 index and return an answer with sources, composed by a deterministic `MockLlmClient` by default. Azure OpenAI + Azure AI Search adapters (profile `azure`, off, fail fast without env vars) and their Terraform (validate only) show how it runs in Azure. All Azure parts are marked `MOCK:`.

**Architecture:** New Maven module `ai` (plain Java 25 + Jackson 3, **no Spring**, no Azure SDK), built between `frontend` and `backend`; `backend` depends on it. It holds the domain of retrieval (`Runbook`, `RunbookChunk`, `RunbookParser`, `Tokenizer`, `RunbookIndex implements Retriever`), the answer side (`LlmClient`, `MockLlmClient`, `PromptBuilder`, `RunbookAssistant`) and the Azure adapters (JDK `HttpClient` against the documented REST APIs). `backend` package `runbook` loads `docs/runbooks/*.md` from the classpath, wires mock or Azure beans by profile and serves `/api/assist`; package `mcp` (from phase 5) gets `RunbookTools`. No cycle: `ai` knows nothing about the backend. Why no Spring AI model starter/Azure SDK: their auto-configuration activates on classpath presence (the profile switch would need exclusions), they add many runtime jars to the Trivy surface, and the two REST contracts are small and stable.

**Tech Stack:** Java 25, Jackson 3 (`tools.jackson.core:jackson-databind`, Boot-managed), JDK `java.net.http.HttpClient`, JDK `com.sun.net.httpserver.HttpServer` (fake Azure in tests), TestNG + Mockito + AssertJ; Azure OpenAI **v1** REST (`POST {endpoint}/openai/v1/chat/completions`), Azure AI Search REST `api-version=2024-07-01`; Terraform 1.17.1, `hashicorp/azurerm` newest 4.x, tflint 0.66.0 + `tflint-ruleset-azurerm` (newest release).

**Spec:** `docs/plans/2026-11-10-roadmap.md` (row 6), `docs/context/cloud-mocks.md` (Azure rows), `docs/context/architecture.md`, `docs/plans/2026-11-10-phase-5-mcp-server.md` (MCP package, `McpResults`, `McpTestClient`, `mcpToken()`, `tools/mcp-verify.sh`). **Prerequisite:** phase 5 is merged; branch `feature/runbook-rag` from an up-to-date `main`.

## Global Constraints
- No secrets in the repo, ever: Azure keys only from env (`AZURE_OPENAI_API_KEY`, `AZURE_SEARCH_API_KEY`), read by `AzureSettings`, never put into `application.yml` (not even as `${VAR}`), never logged (`toString()` redacts), no example values in docs/plans/tfvars. Tests generate keys with `UUID.randomUUID()`.
- Every Azure class/file starts with `// MOCK: <Azure thing> — no Azure account; compiled and tested against a local fake server only, see docs/context/cloud-mocks.md` (Terraform/JSON/Markdown: same text as `#` comment or blockquote). Mock LLM answers start with `MOCK answer (no language model was called).` and the response carries `"mock": true`.
- `ai` module: no Spring, no `java.util.logging`; exceptions are unchecked (`AiBackendException`). Records for data, `final` classes, constructor arguments validated with `Objects.requireNonNull`.
- Answers are grounded: no matching chunk -> fixed text `No runbook covers this question yet.`, sources `[]`, the `LlmClient` is **not** called. Never log the question text (may contain customer data); log source ids and model only.
- Limits: question 1..500 chars; retrieval top 3 for assist, `search_runbooks` limit 1..5 (default 3); each passage sent to a model max 1 500 chars; MCP excerpts max 400 chars.
- Packages: `at.donmatzos.opsdesk.ai` (`RunbookAssistant`, `AssistAnswer`, `AzureSettings`, `AiBackendException`), `.ai.search`, `.ai.llm`; backend `at.donmatzos.opsdesk.runbook`, `at.donmatzos.opsdesk.mcp`.
- Each task ends with `./mvnw -B -ntp verify` green and one commit (explicit paths, `git diff --cached` checked for credentials).

**Decisions:** Parser: title = first `# ` line (fallback: id); a chunk per `## ` section, text before the first `## ` = section `Overview` (skipped when blank); lines inside ``` fences never start a section; `\r\n` normalized. Tokenizer: lowercase, split on `[^\p{L}\p{N}]+`, drop tokens shorter than 2 and a fixed English stop-word list (`a an and are as at be by for from how i in is it of on or the to what when where which why with`), strip one trailing `s` from tokens longer than 3 (`pods` -> `pod`). Index: BM25 (`k1 = 1.2`, `b = 0.75`, idf `ln(1 + (N - n + 0.5) / (n + 0.5))`); document terms = text tokens + title and section tokens added twice (heading boost); results with score > 0 only, sorted by score desc, ties by `runbookId`, then `order`; `limit` clamped to 1..10; blank query -> empty list.
